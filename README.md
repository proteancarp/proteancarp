
I don't want to be confined to a particular technical identity.

Not because specialization is bad, but because I believe an identity can
quietly become a boundary. A backend engineer may naturally look for
backend problems; a data scientist may naturally look for data problems.

I want to approach the problem first, and the discipline second.

**The problem determines the tool.**

AI has made the boundaries between disciplines increasingly porous,
but I believe the harder boundary to cross is the one we build in our
own minds.

So I'm deliberately cultivating flexibility.
